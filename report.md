# Лабораторная работа №5
## Построение бинарного дерева поиска и реализация обходов; вставка и удаление элементов

**Вариант:** 3  
**Seed:** 33  
**Язык программирования:** Python

### 1. Цель работы

Освоить бинарное дерево поиска (BST), реализовать операции вставки, поиска и удаления элементов, четыре вида обхода дерева, вычисление высоты и количества узлов. Проверить правильность реализации и сравнить время поиска в BST и обычном списке.

### 2. Реализация BST

Реализован класс `BST`, содержащий следующие методы:

| Метод | Назначение |
|---|---|
| `insert()` | Вставка нового ключа без дубликатов |
| `search()` | Поиск ключа в дереве |
| `delete()` | Удаление ключа |
| `in_order()` | Обход: лево — узел — право |
| `pre_order()` | Обход: узел — лево — право |
| `post_order()` | Обход: лево — право — узел |
| `level_order()` | Обход дерева по уровням через очередь |
| `height()` | Определение высоты дерева |
| `size()` | Подсчёт количества узлов |

При удалении реализованы три случая: удаление листа, узла с одним ребёнком и узла с двумя детьми. В третьем случае используется преемник — минимальный элемент правого поддерева.

### 3. Проверка правильности работы

Для проверки использована функция `self_check()` из стартовой заготовки.

Проверены:
- Работа с пустым деревом и деревом из одного узла.
- Вставка и поиск ключей.
- Все три случая удаления узлов.
- Правильность четырёх обходов.
- Вычисление высоты и количества узлов.
- Случайные последовательности вставки и удаления со сравнением с эталоном `set` и `sorted`.

Инвариант BST проверялся через `in_order()`: полученная последовательность ключей должна быть строго возрастающей.

**Результат проверки:** `self_check: OK`.

Все предусмотренные проверки завершились успешно.

### 5. Асимптотическая сложность

Время операций BST зависит от высоты дерева `h`.

| Операция | Сложность |
|---|---|
| Вставка `insert()` | O(h) |
| Поиск `search()` | O(h) |
| Удаление `delete()` | O(h) |

На случайных данных высота BST обычно имеет порядок **O(log n)**, поэтому операции поиска, вставки и удаления в среднем выполняются за **O(log n)**.

Если вставлять ключи в уже отсортированном порядке, обычное BST может выродиться в цепочку узлов. В таком случае высота становится равной `n − 1`, а сложность операций ухудшается до **O(n)**.

В отличие от обычного BST, AVL-дерево поддерживает балансировку. Согласно оценке, приведённой в задании, его высота ограничивается величиной порядка **1,44 · log₂(n)**. Благодаря этому основные операции AVL-дерева сохраняют сложность **O(log n)** даже в худшем случае.

Проверка `self_check()` прошла успешно. Эксперимент показал, что на случайных данных поиск в BST работает быстрее линейного поиска в списке.

Установлено, что эффективность операций BST зависит от высоты дерева. При неудачном порядке вставки дерево может вырождаться, поэтому для гарантированно эффективного поиска применяются сбалансированные деревья, например AVL.
